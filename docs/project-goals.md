目标：让用户从提示词、参考图、图片或结构文件出发，在同一个工作台完成生成、预览、编辑、材料统计、项目保存和 Minecraft 文件导出，并保证当前编辑结果能够可靠保存与往返读取。

## 本地交付目标

1. **统一工作流**：10 个 React 工作区共享当前结构；切换页面、打开项目、撤销和重做不混入其他项目的历史。
2. **可信数据**：同一方块 ID 的不同状态分别保留；原点、命名 Region、方向属性和受支持 NBT 元数据在转换中不被静默抹掉。
3. **所见即所导**：AI 建筑编辑后，以当前方块导出；旋转和镜像同步改变坐标、区域、方块朝向和 NBT 位置，旧生成方案不能覆盖编辑结果。
4. **明确失败**：损坏输入在更新项目之前被拒绝；导出失败可以重试；存储不可用、空间不足或内容损坏时给出恢复提示和项目下载入口。
5. **可重复验证**：构建引擎和当前 Worker 后运行浏览器测试；后台启动必须确认实际服务和前端资源可用。

## 本轮补齐的缺口

- 修复调色板按 ID 合并导致不同方块状态丢失，以及 SchematicLike 转换丢失 properties。
- 修复 Litematic 实体、方块实体、待执行方块 tick、NBT long/byte array 的往返；校验重复区域名、区域尺寸、截断数据和非法 palette 引用。
- 从当前编辑结构生成紧缩命名区域，避免导出旧 AI plan；保留负原点，并修正负尺寸区域的导入边界。
- 同步旋转和镜像的方块状态、Region 与 NBT；大结构合并使用迭代边界，专项测试覆盖 40 万方块。
- 保证失败的核心编辑不污染撤销历史；填充改为坐标索引，专项测试覆盖 10 万方块填充。
- 校验外部项目、BlockGrid 和本地恢复数据；JSON 显式编码 NBT bigint 与字节数组；存储失败可恢复，提示词更新不重复序列化大结构。
- 构建自动同步 Worker；测试拒绝陈旧 Worker；开发代理跟随 API 端口；后台启动保存日志并检查就绪。
- 从干净源码构建所需 Craftmatic runtime，消除对旧 vendor/dist 的隐式依赖；原生 placement 的 origin 数组和子区域包装兼容导入导出。
- 服务端模型脚本使用 QuickJS 隔离上下文，设置执行时限和内存上限；死循环、宿主访问、内存耗尽和吞掉方块预算错误均有回归。
- 两套 3D 预览按需加载，Three 核心/WebGL 独立缓存；加载失败可保存当前工作后重载，关闭自动保存时同样可恢复。资源包状态以实际加载完成为准，失败时可重试。

## 验收命令

```powershell
npm run verify
```

该命令串行运行引擎、CLI、服务端、结构编辑、项目状态、工具链、类型检查、生产构建和隔离浏览器验收。浏览器套件不会调用真实模型；具体回归脚本见 `engine-status.md`。
